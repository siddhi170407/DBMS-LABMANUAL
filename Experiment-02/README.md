# Experiment 2: Relational Schema Using MySQL Constraints

## Aim

To convert the Entity-Relationship (ER) diagram of an Indian e-commerce platform into a relational database schema using MySQL constraints and demonstrate referential integrity violations.

## Objectives

- Convert entities and relationships into relational tables.
- Implement primary keys and foreign keys.
- Apply NOT NULL, UNIQUE, CHECK and DEFAULT constraints.
- Understand referential integrity between related tables.
- Demonstrate errors caused by invalid foreign-key references.

## Theory

A relational schema represents the logical structure of a database using tables, attributes, primary keys and foreign keys.

Each entity in an ER diagram is converted into a table. Attributes become columns, and relationships are implemented using foreign keys.

### Types of MySQL Constraints

**1. PRIMARY KEY**

Uniquely identifies each record in a table. It does not allow NULL or duplicate values.

**2. FOREIGN KEY**

Establishes a relationship between two tables and ensures that referenced values exist in the parent table.

**3. NOT NULL**

Ensures that a column cannot contain NULL values.

**4. UNIQUE**

Prevents duplicate values in a column.

**5. CHECK**

Ensures that inserted values satisfy a specified condition.

**6. DEFAULT**

Provides a default value when no value is specified during insertion.

## Relational Schema

The following tables are created:

| Table | Primary Key | Foreign Key |
|---|---|---|
| Customer | Customer_ID | — |
| Seller | Seller_ID | — |
| Product | Product_ID | Seller_ID |
| Orders | Order_ID | Customer_ID |
| Order_Item | Order_Item_ID | Order_ID, Product_ID |
| Payment | Payment_ID | Order_ID |
| Delivery | Delivery_ID | Order_ID |

## Referential Integrity

Referential integrity ensures that a foreign-key value in a child table must reference an existing record in its parent table, unless NULL is permitted.

For example, an order cannot be assigned to a customer who does not exist in the Customer table.

### Referential Integrity Violations

**Violation 1: Invalid Customer Reference**

Attempting to insert an order with a Customer_ID that does not exist in the Customer table causes a foreign-key constraint error.

**Violation 2: Invalid Seller Reference**

Attempting to insert a product with a nonexistent Seller_ID violates the foreign-key constraint.

**Violation 3: Deleting a Referenced Customer**

Attempting to delete a customer who has existing orders fails when the foreign key uses the default RESTRICT/NO ACTION behavior.

## Procedure

1. Create a MySQL database.
2. Create tables based on the ER diagram.
3. Define primary keys and foreign keys.
4. Apply NOT NULL, UNIQUE, CHECK and DEFAULT constraints.
5. Insert valid sample records.
6. Execute queries that intentionally violate foreign-key constraints.
7. Observe the error messages generated by MySQL.
8. Verify that invalid operations do not modify the database.

## Expected Output

- Seven relational tables are created successfully.
- Valid records are inserted into the database.
- Invalid foreign-key references generate errors.
- Attempts to delete referenced parent records are rejected.
- Database relationships remain consistent.

## Result

The ER diagram was successfully converted into a relational schema using MySQL constraints. Referential integrity was demonstrated through valid operations and intentional foreign-key violations.

## Conclusion

MySQL constraints maintain database accuracy, consistency and integrity by preventing invalid data and enforcing relationships between tables.
